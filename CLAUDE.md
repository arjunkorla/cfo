## CFO Workspace — data modes (sample-data-first)
- **Default: local sample data.** Every category and agent works with no backend API, database, authentication or LLM connection. Normal use never shows "Data source not connected".
- **Optional demo scenarios: only when explicitly requested** — the `?demo=error|empty|loading` previews of non-success states. They never run by default.
- **Live API mode: disabled.** It does not exist in the code. Adding it, or any transition to live data, requires separate explicit authorization.
- **Never silently switch** from sample data to a disconnected production mode, and never reintroduce rolled-back functionality (production default, `NOT_CONNECTED` data source, `MODE`/`?mode=demo`, the `==DS==`/`==R2==` regions, the 30 s timeout/AbortController request layer) without explicit authorization.
- **Preserve the `CFO_SAMPLE` architecture:** a separate file (`components/cfo-sample-data.js`) loaded before the page scripts, exposing `listAgents`, `getSummary` and `answer` (plus `listCategories` for search and the `format` helper). The UI talks only to these. Keep their data contracts stable and API-compatible (see `architecture.md` → *Sample data layer*); a future backend replaces the functions, not the UI.
- **Keep all 8 categories and 32 agents functional,** each with its own dataset, summary (3 insights · 2 risks · 2 recommendations, each with a sample source), chart and 3 suggested questions with answers.
- **Consistent figures:** summary, chart and chat use the same sample values. A metric shown in several places has one value (e.g. total AR $8.6M, overdue AR $2.4M = 28%, DSO 48 days, CEI 86%, auto-match 91%, unapplied $500K, 342 disputes / $1.25M, bad-debt exposure $420K). Change a figure everywhere or nowhere.

## Platform-wide rules (always apply, both tracks)
- **Data honesty:** never present sample values as real Emagia or customer data, and never claim a connected service, AI model or execution result that doesn't exist. Sample data is deterministic, illustrative and visibly labelled ("Sample data", "Assistant · sample response", "Model: Not called — local sample data"). Sample chat replies are local, rule-based responses and are never labelled as AI output.
- **Origin labelling:** every value is identifiable as actual, sample/demo (synthetic), calculated, forecast, rule-based or AI-generated. Rule-based output is never labelled AI. Forecasts are labelled provisional and never presented as actuals. Sample data is never mixed with actual data.
- **Methodology:** calculations, thresholds and forecasts are provisional until Finance/Product sign-off. Each exposes its formula, inputs, period, assumptions and origin. Missing inputs return "unavailable"; they are never invented or silently substituted. Illustrative assumptions (e.g. the bad-debt loss rates) are stated as such.
- **Human control:** human approval is required for consequential financial actions. No autonomous changes to credit limits, payment records, customer accounts or customer communications. Execution stays disabled until an authorized service is connected and confirms it.
- **Security:** no secrets or LLM keys in browser code; LLM access only via a server-side gateway. Roles, approvals and tenant/company isolation are enforced server-side; the browser only reflects them. Treat external and user-provided content as untrusted.
- **Audit:** never claim persistent or compliance-grade audit storage that doesn't exist. Never use localStorage as audit or financial storage.
- **Accessibility:** WCAG 2.2 AA; never communicate status by colour alone; keyboard and screen-reader support for every interaction.
- **Design system:** primary `#1E439B` is locked; no dark mode; no new tokens, CDNs, second design system or unnecessary dependencies. `design.md` and `design-system.md` change only with separate approval.
- **Scope:** change only what the task asks. Before editing, state the exact functions, components or blocks you will touch.
